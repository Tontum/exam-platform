# 04 - 功能模块详细设计

> 本文档定义教师培训在线考试系统各功能模块的详细需求、页面交互、业务规则和边界条件。基于原始项目笔记和逐字稿的业务逻辑整理而成。

---

## 系统整体结构

系统采用**项目制**，分为三端：
- **学员端（前台）**：老师/学员登录后进行培训考核
- **管理端（前台）**：校长登录后发布试卷、批阅试卷
- **管理后台**：管理员登录后对项目进行功能配置和权限分配

---

## 一、用户与角色模块

### 1.1 角色定义

| 角色 | 编码 | 权限概述 |
|------|------|----------|
| 管理员（admin） | 1 | 项目配置、功能开关、角色权限分配 |
| 校长/管理端（principal） | 2 | 发布试卷、批阅试卷、查看统计 |
| 老师/学员（teacher） | 3 | 查看试卷、答题提交、查看成绩 |

### 1.2 层级管理

每个用户在 `user` 表中维护四个层级字段：省 → 市 → 县 → 校。

**业务意义：**
- 校长发布试卷时可按层级选择目标老师（如只给"郑州市"的老师发卷）
- 数据过滤：河北的老师不能看到河南的试卷内容
- 试卷标记归属：区分"省级试卷""市级试卷""校级试卷"
- response 表中冗余层级字段，支持按区域统计

### 1.3 项目制

- 老师登录后首先看到**项目列表**（可参加多个项目）
- 点击"进入项目"后，左侧展示该项目已启用的功能菜单
- 管理员在后台为每个项目配置可用工具和角色权限
- 项目与用户为 N:M 关系，通过 `project_user` 中间表关联

## 二、试卷工具模块（核心）

### 2.1 功能概述

试卷工具是系统的核心功能，类似画图工具，是系统中的一个功能模块。主要用于：教育厅定期对全省老师进行线上考核，校长给老师发布试卷考核。

### 2.2 校长发布试卷

**操作流程：**

1. 校长登录管理端，点击"发布试卷"
2. 填写试卷基本信息表单：
   - 考核名字（试卷名称）
   - 答题规定时间（分钟）
   - 及格分数线
   - 总分
   - 所属项目
3. 提交 → 生成 paper 记录（状态=草稿）
4. 添加题目（在草稿状态下编辑）：
   - 题目类型：单选题、多选题、判断题、主观题
   - 题干内容、题目分值、是否必答
   - 对于选择题和判断题：添加选项，标注正确答案
5. 选择题目的分发范围（按层级筛选老师）
6. 点击"正式发布"：
   - paper 状态 → 已发布
   - 向 Kafka 发送分发消息
   - 异步向 response 表批量插入记录（每个选中老师一条）
   - 前端提示"分发中"，200ms 内返回

**业务规则：**
- 主观题不设标准答案，依赖校长后续批阅
- 试卷发布后不可修改（需先下线）
- 若 config 表中配置了发布时段限制，需校验
- 支持选择 1 万+ 老师发布，通过 Kafka 异步保障体验

### 2.3 老师答题

**操作流程：**

1. 老师登录学员端，在项目中点击"试题"菜单
2. 展示试卷列表（查询 response 表按 user_id，含状态标签）：
   - 未答题（状态=0）→ 显示"开始答题"按钮
   - 正在答题（状态=1）→ 显示"继续答题"按钮
   - 已提交（状态=2）→ 显示"查看详情"按钮
   - 已批阅（状态=3）→ 显示"查看成绩"按钮
3. 点击"开始答题"进入试卷：
   - 查询 question 表显示题目
   - 查询 option 表显示选项
   - response 状态更新为 1（正在答题）
4. 答题过程中：
   - 每道题提交时，答案写入 Redis（实时存储）
   - 每 3 秒自动保存一次进度到 Redis
   - 若断网/断电重进，可从 Redis 恢复进度
   - 前端每 5 秒调一次保存接口，确保状态保持"正在答题"
5. 点击"提交试卷"：
   - response 状态 → 2（已提交），记录提交时间
   - Redis 中该试卷答题数据批量落库到 answer 表
   - 客观题（选择题、判断题）自动批阅：
     - 比对 answer.answer_content 与 option.is_correct
     - 写入 answer.is_correct 和 answer.score
   - 跳转回试卷列表

**边界处理：**
- 答题倒计时归零时自动提交
- 答题过程中意外退出，"继续答题"而非重新开始
- 提交按钮一旦点击，前端传状态=2，关闭定时保存任务

### 2.4 校长批阅试卷

**操作流程：**

1. 校长进入"批阅试卷"页面
2. 选择某份试卷 → 查看所有老师答题列表
3. 点击某位老师 → 查看每道题的作答内容：
   - 客观题：显示老师选择的选项、正确答案、自动判分结果
   - 主观题：显示老师的文字作答
4. 逐题批阅：
   - 给每道题打分（更新 answer.score）
   - 可添加批阅评语（answer.review_comment）
   - 客观题自动判分结果可人工修正
5. 确认批阅完成：
   - 汇总各题分数 → 写入 response.score
   - 判断是否合格 → response.is_pass（score >= paper.pass_score）
   - response 状态 → 3（已批阅）

**配置项（由后台管理员设定）：**
- 是否允许校长批阅（allow_review）
- 主观题是否自动给分（auto_score）
- 是否可以只出主观题或只出客观题

### 2.5 数据补偿机制

**场景：** 校长发布试卷时选了 100 个老师，后续项目又新增了 50 个老师，新老师看不到已有的试卷。

**处理逻辑：**
- 老师点击"试题"时，先查 response 表是否有记录的 paper_id
- 若某份试卷在 paper 表中存在但 response 中没有该老师的记录
- 系统自动按层级判断该老师是否在试卷目标范围内
- 符合条件则补插入 response 记录

## 三、文章工具模块

### 3.1 功能概述

项目内发布文章、查看文章、评论互动、调查问卷。

### 3.2 核心特性

- 校长/管理员可发布文章
- 文章支持富文本编辑
- 学员可查看文章、评论
- 支持调查问卷（扩展）
- 发布时段控制（通过 config 表）：不在允许时段内发布则提示"不在发布时间内"
- 数据过滤：河北学员看不到河南老师的文章（按层级过滤）

## 五、配置管理模块（管理后台）

### 5.1 管理员操作流程

1. 管理员登录后台
2. 看到项目列表，选择一个项目进入
3. 顶部显示角色 Tab（学员 / 校长 / 管理员）
4. 点击某个角色 → 配置该角色在本项目中的权限：
   - 哪些工具菜单可见（is_enabled）
   - 哪些操作按钮可用（如：发布、删除、批阅）
5. 点击某个工具 → 配置该工具的规则：
   - 是否必须设置合格分
   - 发布时间段限制
   - 每次提交/阅读获得的考核加分

### 5.2 权限判断逻辑

- 用户登录 → 获取角色 → 查询 config + permission 表
- 前端根据权限结果渲染两套页面：
  - 有权限 → 显示菜单/按钮
  - 无权限 → 隐藏菜单/按钮，或按钮置灰不可点击

## 六、统计与考核模块

### 6.1 分数统计

- 按试卷维度统计：平均分、合格率、各分数段人数
- 按区域维度统计：省级、市级、县级、校级合格率对比
- 按时间维度统计：周报、月报
- 使用 Redis 实时累加 + 凌晨定时落库方案
- 分布式锁（Redis SETNX + Redisson 看门狗）保证单实例执行

### 6.2 考核积分

- 学员每提交一次试卷 → 加考核分（分值由 config.score_per_submit 配置）
- 学员每看一篇文章 → 加考核分（分值可配置）
- 考核分与试卷得分独立计算
- 凌晨错峰定时任务汇总考核积分

### 6.3 阶段考核

- 项目可分阶段
- 第一阶段任务未达标 → 不允许进入第二阶段
- 由 config 表配置阶段规则

## 七、系统边界与异常处理汇总

| 场景 | 处理策略 |
|------|----------|
| 1 万+ 老师并发发卷 | Kafka 异步 + 批量 500 条插入 |
| 老师答题中断电/断网 | Redis 每 3 秒自动保存，重连后恢复 |
| 新增老师缺少试卷 | 查询时按需补偿 response 记录 |
| Redis 落库失败 | 标记"待处理"，1 分钟后重试 + 告警 |
| 定时统计任务并发执行 | Redis 分布式锁 + SETNX |
| 缓存与 DB 不一致 | 更新 DB → 删除缓存，短有效期内自动失效 |
| ES 同步延迟 | Canal 实时 + 每小时补偿对账 |
| 10 万+ 老师同时查试卷 | 多级缓存（Caffeine + Redis + Sentinel 限流） |
| 分布式锁超时 | Redisson 看门狗自动续期 + 业务拆分小任务 |
